## 三、开发过程中遇到的问题及解决方式

| 问题 | 现象 | 解决方式 |
|---|---|---|
| **素材包子目录未被打包** | 运行时读 manifest 报「素材包清单读取失败」，`build/web/assets/assets/packs/` 下只有 `.gitkeep` | Flutter 的目录资产声明**不递归子目录**（只收录直接子文件）。在 pubspec 显式声明 `assets/packs/memory_match/`、`assets/packs/whack_mole/`、`assets/packs/jigsaw/` 三个子目录后解决 |
| **离线环境 Web 首帧白屏** | `flutter clean` 后重建，页面加载 main.dart.js 与字体后停滞，Canvas 不渲染、无 JS 报错 | Flutter Web 默认从 gstatic CDN 拉取 CanvasKit，离线时静默卡死。构建加 `--dart-define=FLUTTER_WEB_CANVASKIT_URL=canvaskit/` 强制使用构建内本地渲染器（已写入 `tool/qa/verify_m2.js` 头部说明，后续里程碑构建命令需带上） |
| **验收脚本状态竞态** | 固定延时等待解锁/失败态偶发过早或过晚；下载完成导致网格重排后，用旧截图坐标点击落空 | ① 改为「轮询等待特征色出现」（primary+star=解锁、primary 无 star=失败）；② 面板内关闭钮/下载钮相对表头图标偏移恒定，用「一次取色 + 确定性偏移点击」压缩入队前耗时，确保拍到排队态 |
| **像素分析器 key 前缀不一致** | 脚本等待超时但现场截图明明有目标色块 | `board_analyzer.py` 返回的 `key` 是冒号前缀（`primary`），脚本却在比对完整 `primary:#FFB627`；比对统一改为取 `key.split(':')[0]` |
| **pop 后使用已卸载 context** | 占位游戏点「开始玩」先 pop 面板再弹 Toast 存在隐患 | 调整为先用仍挂载的 context 弹 Toast 再 pop |

## 四、遗留问题与后续建议

1. **Wi-Fi 策略为软实现**：网络源（局域网/托管）要求 Wi-Fi 的约束目前通过「默认不配置网络地址 + 本地源离线兜底」保证（演示环境实际全程零联网），未接 `connectivity_plus` 做蜂窝网络硬阻断；建议 M3/M4 接入后补上。
2. **占位游戏为空素材包**：打地鼠/拼图 manifest 为空清单（md5=空串摘要），解锁后「即将上架」；M4 实装后由 `tool/pack_generator.py` 重新生成真实清单即可，流程无需改动。
3. **`docs/shortscreens/` 存在少量中间轮次旧截图**（文件名编号相同但描述不同，如 `2-17-单队列-排队中.png` 为旧版），有效交付集见本记录验证表所列文件；本环境删除命令多次审批超时未清理，建议手动删除非表内文件。
4. **下载调试入口**现位于家长中心（显式开关 + 长按快捷触发），M3 家长门落地后应将其收敛到门内，避免儿童触达。
5. 下载动画时长（约 6s）为演示节奏所设（`_pace` 60×100ms），真实网络源接入后应改为按实际字节流推进。
