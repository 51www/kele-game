# UI 设计规范 —— 《童趣游戏盒》

> 版本：v2.0 ｜ 日期：2026-10-29 ｜ 技术栈：Flutter（Android 优先）
> 结构说明：§0 风格定位与提示词 → §1~§5 项目 Token 表（具体数值）→ §6 组件规范 → §7 页面规范 → §8 通用硬性规则（保留）→ §9 交付自检清单。
> 核心原则不变：**先定 Token，再写 UI；一切视觉属性只允许引用 Token，禁止散落魔法值。**

---

## 0. 风格定位与参考风格提示词

### 0.1 风格定位

- **一句话**：糖果色卡通休闲游戏风——深紫底 + 奶油卡片 + 马卡龙瓷砖色 + 萌系动物吉祥物，全部圆角无锐角。
- **目标用户**：3~9 岁儿童（直接操作者）+ 家长（家长中心使用者）。儿童区必须"不识字也能用"：大图标、大按钮、强色彩区分、拟物按压感。
- **签名元素**：**糖果厚底按钮**——所有可按压元素都带"深色底部厚边"，按下时整体下沉 2px，制造果冻/软糖按压感。这是全 App 最具辨识度的交互语言。
- **分区策略**：儿童区（大厅/游戏内）= 深紫渐变底、高饱和糖果色；**家长中心 = 降饱和奶油底棕字**，视觉上明确告知孩子"这不是你玩的地方"，同时降低家长操作的兴奋感。

### 0.2 参考图风格提示词（供 AI 生成素材 / 美术对齐用）

**中文版：**

> 休闲益智手游 UI，卡通儿童向。深紫罗兰渐变背景（#6C5CE7→#8E7CF3），顶部圆形紫色图标按钮带深紫描边与厚底边，伪 3D 按压感；信息卡为奶油米黄底配棕色粗体字与大圆角；主游戏区为纯白超大圆角面板；棋盘瓷砖为大圆角方块，马卡龙高饱和配色（薰衣草紫、柠檬黄、樱花粉）配白色粗描边图标；橘色萌系狐狸/小猫吉祥物点缀；底部深紫横幅配白色超粗标题与星星装饰；整体糖果色、无锐角、粗描边、软阴影、Baloo 风格圆润字体，儿童友好。

**英文版（图生图/素材生成直接可用）：**

> cute casual mobile game UI for kids, candy pastel palette on deep purple gradient background (#6C5CE7 to #8E7CF3), chunky rounded buttons with darker purple bottom rim, 3D pressed effect, cream parchment info cards with bold brown text and large corner radius, clean white game panel with extra rounded corners, macaron tiles in lavender purple / lemon yellow / sakura pink with bold white icons, kawaii orange fox mascot, dark purple banner with extra-bold white title and star sparkles, rounded display font, soft shadows, no sharp corners, thick outlines, high saturation, child-friendly, kawaii style

**素材生成硬性约束**（所有游戏共享角色库，出自计划书 §7）：

1. 角色统一为萌系动物/水果，2~3 头身，粗描边、高饱和；
2. 全套素材共享同一描边粗细与阴影方向（左上光源）；
3. 图标必须面性（filled），禁止线性图标混入；
4. 每个游戏主题色从 §1.2 瓷砖色板中取，不得自造新色。

## 2. 间距 Token（4px 基数，7 档）

| Token | 值 | 语义 |
|---|---|---|
| `space.xs` | 4 | 图标与文字间距 |
| `space.sm` | 8 | 组件内部元素间距 |
| `space.md` | 12 | 组件内边距（小） |
| `space.lg` | 16 | 组件内边距 / 组件间 |
| `space.xl` | 24 | 卡片内边距 / 区块内 |
| `space.xxl` | 32 | 区块间 |
| `space.xxxl` | 48 | 页面级大分区 |

页面水平安全边距统一 `space.xl`（24）。儿童触控目标放大：**所有儿童可点元素 ≥ 56×56**（高于 44 标准），家长中心 ≥ 44×44。

## 3. 字体 Token

字体：标题用**霞鹜文楷**（手写感、圆润、亲和），正文/数字用**思源黑体**（免费商用，出自计划书 §7）。字重只用 2 种：Regular + Bold。

| Token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `font.display` | 32/40 | Bold | 结算星星数、庆祝大字 |
| `font.title` | 24/32 | Bold | 页面标题（关卡名、大厅标题） |
| `font.heading` | 18/26 | Bold | 卡片标题、按钮大字 |
| `font.body` | 16/24 | Regular | 正文、游戏说明 |
| `font.caption` | 13/18 | Regular | 辅助说明、家长中心正文 |
| `font.mini` | 11/16 | Bold | 角标（未读数、大小标签） |

儿童区正文最低 `font.body`（16），禁止更小；文字截断：游戏名单行省略，说明文字最多 2 行省略。

## 4. 圆角 Token（梯度：小 ≤ 中 ≤ 大 ≤ 最大）

| Token | 值 | 用途 |
|---|---|---|
| `radius.sm` | 8 | 角标、mini 标签 |
| `radius.md` | 16 | 按钮、输入框、游戏瓷砖 |
| `radius.lg` | 24 | 卡片、白面板、大厅宫格 |
| `radius.max` | 32 | 弹窗、结算页 |
| `radius.pill` | 999 | 进度条、胶囊标签、圆形图标按钮 |

同类元素圆角严格一致；**全 App 无直角元素**。

## 5. 阴影与动效 Token

### 5.1 阴影（仅 2 种，全局唯一）

| Token | 定义 | 用途 |
|---|---|---|
| `shadow.rim` | 底边同色系加深 2~4px（如 `btn.primaryRim`），无边框线 | 所有可按压元素（签名元素） |
| `shadow.card` | `0 6 16 rgba(61,42,84,0.18)` | 卡片、面板、弹窗 |

禁止第三种阴影；禁止运行时改阴影颜色。

### 5.2 动效

| Token | 值 | 用途 |
|---|---|---|
| `motion.fast` | 150ms + easeOut | 按压下沉/回弹、悬停反馈 |
| `motion.normal` | 250ms + easeOutBack | 弹窗出入、卡片出现（轻微 Q 弹） |
| `motion.celebrate` | 800ms + 自定义关键帧 | 解锁星星动画、结算星星落下、护眼结束庆祝 |

规则：按压反馈全局只有一种实现——**按下整体下沉 2px、厚底边同步压缩 2px**；护眼休息动画不可跳过但时长固定（计划书 §5）。

## 6. 组件规范

### 6.1 按钮（类型 × 尺寸 × 状态完整矩阵）

| 类型 | 样式 |
|---|---|
| 主按钮 | `btn.primary` 底 + 白字 `font.heading` + `radius.md` + `shadow.rim`；高度：大 64 / 中 56 / 小 48 |
| 次按钮 | `panel.bg` 白底 + `neutral.text1` 字 + `shadow.rim`（底边 `#D8D4E8`） |
| 危险按钮 | `semantic.error` 底 + 白字 + `shadow.rim`（底边 `#C43A36`）；仅删除/隐藏游戏等破坏性操作 |
| 图标圆钮 | 紫底 `brand.deep` 描边 + 白图标 + 圆形 + `shadow.rim`（如返回、设置） |

每个视图区域 ≤ 1 个主按钮；主按钮统一用于"玩 / 再玩一次 / 开始"这类前进动作。加载中禁点；按下态走 §5.2 统一按压反馈。

### 6.2 卡片

- **奶油信息卡**：`cream.bg` + `radius.lg` + 棕字，用于规则说明、关卡目标（对齐参考图顶部卡片）。
- **白面板**：`panel.bg` + `radius.lg` + `shadow.card`，游戏主区域、家长中心卡片。
- **大厅游戏卡**：`tile.*` 色底 + `radius.lg` + 大图标（≥ 96px）+ 游戏名（`font.heading`），未下载时右上角显示大小标签（`radius.sm` 深紫底白字 mini）。

### 6.3 弹窗与结算

- **统一结算弹窗**：`panel.bg` + `radius.max` + 顶部三颗 `semantic.star` 星星（`motion.celebrate` 落下）+ 分数（`font.display`）+ 两个大主按钮"再玩一次 / 回大厅"（对齐计划书 §4.3 强制规则）。
- **返回确认弹窗**：游戏内返回必须二次确认，"继续玩"为主按钮、"退出"为次按钮（防误触哭闹，主次分明）。
- **家长门**：进入家长中心前插入算术题弹窗（奶油卡风格 + 数字键盘，键 ≥ 56px）。

### 6.4 进度与反馈

- **下载进度条**：`radius.pill` 胶囊，轨道白底 20% 紫，填充 `tile.lemon`，配 `motion.normal`。
- **Loading**：页面级 = 吉祥物 + 转圈（全局唯一实现）；操作级 = 按钮 Loading；禁止同场景混用骨架屏与 spinner。
- **Toast**：深紫底白字 + `radius.pill`，成功/失败配对应语义色图标；错误必须带恢复动作文案。
- **护眼休息页**：全屏 `bg.primary` + 吉祥物眼保健操动画 + 倒计时（`font.display`），不可跳过。
- **"明天见"锁屏页**：到点后全屏展示，星星+月亮插画，仅一个"知道了"次按钮。

### 6.5 图标与插画

面性风格二选一已定为**面性**，尺寸 3 档：16 / 24 / 32；颜色跟随文字或取中性色阶。吉祥物插画仅出现在：大厅空状态、Loading、结算、护眼页、下载解锁动画五处，禁止滥用。

## 7. 页面规范要点

| 页面 | 关键规则 |
|---|---|
| 游戏大厅 | `bg.primary` 渐变底；"我的游戏"宫格在前、"游戏商店"在后；入口只靠大图标+名字，3 岁可独立操作；家长中心入口置于次要位置并带 🔒 |
| 下载解锁流程 | 下载确认（奶油卡展示大小/适龄）→ 进度条 → 星星解锁动画（`motion.celebrate`）→ 直接进游戏，全链路无文字依赖 |
| 游戏内 | 游戏区 = 白面板；返回圆钮固定左上；暂停/音量圆钮固定右上；任何游戏内禁止外链/分享/广告/充值入口（计划书 §2） |
| 家长中心 | 切换为 `neutral.pageBg` 奶油底 + 白卡 + 深紫字；降饱和、无吉祥物、无动画装饰；仅此区域用 `font.caption` 密排信息 |
| 空状态 | 我的游戏为空时：吉祥物 + "还没有游戏，去商店看看吧" + 主按钮跳商店 |

## 8. 通用硬性规则（项目无关，继续生效）

### 8.0 总则

1. 任何开发前必须以本文档 §1~§5 Token 表为准，后续所有 UI 代码只能引用该表。
2. 同一视觉语义**全局只允许一种实现**：同一个"主要按钮"、同一种"卡片"、同一种"错误提示"，禁止同一语义出现两套写法。
3. 视觉上完全相同的元素必须抽为公共组件复用，**禁止复制粘贴出第二份相似代码**。
4. 修改任何组件样式必须改 Token 或组件定义，**禁止在业务代码里局部覆盖**产生"特例样式"。

### 8.1 间距与边距

1. 间距只能取自 §2 序列，禁止使用序列外任意值。
2. 同一语义的间距全局唯一：页面边距、组件间距、区块间距、图标与文字间距，各只有一个值。
3. 层级越大的分隔用越大的间距档：元素内 < 组件间 < 区块间，必须单调递增，禁止混用。
4. 相关元素间距必须小于不相关元素间距（亲密性原则），分组靠间距表达，禁止只靠分割线。

### 8.2 颜色体系

1. 颜色只允许引用 §1 Token；每种语义只允许一个颜色，禁止挪作装饰。
2. 文字深浅必须使用定义好的色阶表达层级，禁止随意取灰；同层级文字全局同色。
3. `tile.*` 色板禁止用作按钮底色或文字色；紫底上文字必须用 `brand.onPurple`。
4. 品牌色的悬停、按下、禁用态必须为预定义派生 Token，禁止运行时用透明度、滤镜临时生成。
5. 页面背景、卡片背景层级关系固定（bg < cream < panel），禁止反转。

### 8.3 字体层级

1. 字号只允许来自 §3 字阶；每一级"字号+行高+字重"三件套固定，禁止拆开单改。
2. 相同信息类型必须使用同一层级，禁止同级不同样式；字重只用 Regular + Bold。
3. 行高必须显式设置；强调优先用字重与颜色表达，禁止斜体、下划线混搭强调。

### 8.4 按钮与组件一致性

1. 按钮必须覆盖 §6.1 完整矩阵（类型 × 尺寸 × 状态），缺一不可；每视图区域 ≤ 1 个主按钮。
2. 破坏性操作必须用危险样式 + 二次确认（且触发家长门）。
3. 输入框、下拉、开关、卡片、弹窗、标签每类组件只允许一套实现；必须覆盖默认/聚焦/错误/禁用四态。
4. 圆角按 §4 梯度执行，同类元素严格一致。
5. 表单结构全局统一（家长中心）：label 位置、间距、错误提示位置与样式一致。

### 8.5 交互反馈

1. 任何异步操作必须有两种反馈：进行中 + 结果；同类场景全局只用一种方式。
2. 错误提示方式全局固定：字段级错误内联显示并标红输入框；全局性错误用统一 Toast；禁止同一场景时弹窗时内联。
3. 所有错误必须给恢复路径，禁止死胡同式报错。
4. 页面必须有**加载 / 空 / 错误 / 正常**四态设计，缺任何一态不许上线。
5. 动效只允许 §5.2 三档时长与曲线，同类交互动画一致；所有可点元素必须有可见按下反馈。

### 8.6 响应式适配

1. 断点固定 3 档：手机竖屏 / 手机横屏 / 平板（含横竖），全局文档化，禁止局部自定义断点。
2. 布局采用移动优先，全项目统一。
3. 任何断点下不得出现非预期横向滚动、元素重叠、文字截断异常；儿童可点元素 ≥ 56px。
4. 游戏画布（Flame）与 UI 层分离：游戏画布等比缩放居中，UI 控件按断点规则排布；图片素材必须预留占位，禁止加载后撑开布局。
5. 导航模式按断点全局统一，禁止同一断点内页面间导航形态不一致。

## 9. 交付前自检清单（Agent 必须逐项核对）

- [ ] 代码中无表外间距 / 颜色 / 字号 / 圆角 / 阴影 / 动效值，全部引用 §1~§5 Token
- [ ] `tile.*` 色板未被挪作按钮/文字色；语义色未被挪作装饰
- [ ] 同一语义组件全局只有一种实现，无复制粘贴变体
- [ ] 按钮"类型 × 尺寸 × 状态"矩阵完整，每视图区域 ≤ 1 个主按钮
- [ ] 所有可按压元素带 `shadow.rim` 厚底边，按压下沉反馈统一（签名元素）
- [ ] 儿童可点元素 ≥ 56×56；游戏内返回二次确认、家长门触发正确
- [ ] 页面四态（加载/空/错误/正常）齐全；错误有恢复路径
- [ ] 统一结算弹窗（星星+两按钮）被所有游戏复用，无自造结算页
- [ ] 儿童区/家长中心视觉分区正确（紫底糖果色 vs 奶油底降饱和）
- [ ] 游戏内无外链/分享/广告/充值入口
