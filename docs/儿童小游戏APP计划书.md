# 《童趣游戏盒》本地小游戏 APP 开发计划书

> 版本：v1.0 ｜ 日期：2026-10-28 ｜ 技术栈：Flutter
> 定位：面向 3~9 岁（幼儿园~三年级）孩子的**本地休闲小游戏合集**，无广告、无内购、无联网依赖，家长完全可控。

---

## 1. 项目概述

### 1.1 背景

市面小游戏广告泛滥、内购陷阱多，低龄孩子无法独立使用。计划自研一款装在自己设备上的游戏合集 App，汇总 19 款适龄小游戏，只作本地娱乐。

### 1.2 目标

- 一款 Flutter App（Android 优先，iOS 侧载为辅），**不上架、不发布**，仅家庭设备侧载安装。
- 囊括 19 款启蒙/学龄休闲游戏，覆盖 3~9 岁。
- 游戏以"**游戏中心 + 单独下载解锁**"的形式呈现：打开 App 只见游戏大厅，每个游戏首次使用需单独"下载"，下载后永久离线可用。
- 内建儿童保护：家长门、护眼计时、防误退出。

### 1.3 非目标（明确不做）

- ❌ 不上架任何应用商店，不做账号体系、不做排行榜联网对战
- ❌ 不接任何广告 SDK、统计 SDK
- ❌ 不做社交、聊天、外链分享

---

## 2. 产品形态与核心体验

```
┌─ 游戏大厅（打开即见）─────────────┐
│  [我的游戏] 已下载的游戏九宫格      │
│  [游戏商店] 待下载游戏（含大小/适龄）│
│  [家长中心]（入口带家长门🔒）       │
└──────────────────────────────────┘
        │ 点击未下载的游戏
        ▼
  下载确认 → 进度条 → 解锁动画 → 直接进入游戏
        │ 之后点击已下载游戏
        ▼
  秒开进入 → 单局结束 → 统一结算页（星星/分数）→ 返回大厅
```

**核心体验规则：**

1. 大厅只展示大图标 + 游戏名，3 岁孩子无需识字即可点击进入。
2. "下载"过程要有仪式感（进度条 + 解锁星星动画），制造"获得新游戏"的期待感。
3. 下载后游戏永久本地可用，断网零影响。
4. 任何游戏内不允许出现：外部跳转、分享按钮、广告位、充值入口。

## 4. 技术架构

### 4.1 关键技术决策："单独下载再使用"怎么实现

**Flutter 的硬限制：Dart 代码 AOT 编译，无法像 H5 那样运行时加载新的游戏逻辑包。** 因此"下载解锁"必须变通，方案对比如下：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **B-1 素材包解锁（推荐起步）** | 游戏逻辑全部内置 APK，美术素材+关卡数据按游戏拆成资源包，"下载"= 拉取资源包后解锁入口 | 100% 离线、实现最稳、体验与真下载无差别 | 需要"下载源"或首包较大 |
| B-2 仪式化解锁（最简） | 资源也全部内置，"下载"仅播放本地解锁动画（本地复制） | 零网络依赖、一天就能实现 | 严格说是"假下载" |
| A H5 游戏容器（远期扩展） | 游戏做成 HTML5 包（zip），App 内 WebView 加载，游戏包真正按需下载 | 可无限扩充开源 H5 游戏 | 与"全 Flutter"目标偏离，性能/体验降级 |

**选型结论：**

- **第一版采用 B-1**：APK 内置全部游戏逻辑；每个游戏的素材包（约 2~10MB）通过内置的下载管理器获取。下载源三选一（可并存，按优先级回退）：
  1. **家庭局域网源**：NAS/旧电脑起一个静态 HTTP 服务（家长自己控制内容更新）；
  2. **静态托管**：对象存储 / GitHub Pages 直链（配 MD5 校验）；
  3. **本地兜底**：资源文件放在设备存储指定目录，手动拷入即视为"已下载"。
- **架构上预留 A（H5 容器）**：GameModule 接口同时定义 `native` 与 `webview` 两种实现类型，未来想接入海量开源 H5 小游戏时无需改大厅。

### 4.3 统一游戏框架（GameModule 接口）

每个游戏实现同一抽象，保证大厅无差别接入：

```dart
abstract class GameModule {
  String get id;                  // 唯一标识
  String get name;                // 名称
  int get minAge;                 // 适龄下限
  Size get packSize;              // 素材包大小
  Future<void> init(GameConfig config);   // 注入难度/素材路径
  Widget buildGamePage(BuildContext context);
  void pause();  void resume();  void dispose();  // 护眼计时/切后台
  Stream<GameResult> get resultStream;    // 统一结算（分数/星星/用时）
}
```

**框架强制的统一规则：**

1. 所有游戏共用统一结算弹窗（星星 + 分数 + "再玩一次 / 回大厅"两个大按钮）。
2. 所有游戏内返回必须二次确认（防误触哭闹）。
3. 所有游戏遵守全局音量开关与护眼暂停（计时到点框架直接冻结游戏画面）。
4. 难度配置由家长中心下发（如：连连看去倒计时、贪吃蛇降速）。

### 4.4 关键子系统

| 子系统 | 设计要点 |
|---|---|
| **下载管理器** | 下载队列（同时仅 1 个，孩子不排队焦虑）、Wi-Fi 才允许（默认）、MD5 完整性校验、失败三次后转"本地导入"引导 |
| **家长门** | 进入家长中心需通过：两位数算术题（如 13+8）或长按 3 秒，随机轮换防 memorize |
| **护眼计时** | 连续玩 20 分钟弹休息动画（眼保健操引导 30 秒）；每日总时长家长可设（默认 40 分钟），到点锁屏至次日 |
| **进度存储** | SharedPreferences + 每游戏一个 json（分数/星级/解锁状态），本地备份导出 |
| **音频** | 全局统一的柔和音效包，独立音乐/音效开关（家长中心控制） |

## 5. 儿童保护与家长功能清单

| 功能 | 规则 |
|---|---|
| 家长门 | 算术题解锁，进入家长中心与"删除游戏"操作时触发 |
| 护眼休息 | 每 20 分钟强制休息动画 30 秒，不可跳过 |

| 无干扰承诺 | 全 App 无广告、无外链、无内购、无分享 |
| 游戏管理 | 家长可隐藏某个游戏（如睡前隐藏跳一跳这类兴奋类游戏） |

## 7. 素材与版权策略

1. **美术统一自产**：用 AI 生成一套统一风格素材（萌系动物/水果主题，高饱和、大图标），19 个游戏共享角色库——比逐个找开源素材更统一、无版权风险。
2. **代码来源**：⭐ 标记游戏优先参考开源实现（MIT/Apache 优先），每个项目入库时登记来源与 License；License 不明的只参考思路、代码重写。
3. **音效**：使用 CC0 素材站（freesound CC0 区等），或 AI 生成柔和音效。
4. **字体**：使用免费商用字体（如霞鹜文楷、思源黑体）。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Flutter 无法动态加载游戏逻辑 | "下载"体验受限于素材包 | 已选 B-1 方案；预留 H5 容器扩展 |
| 素材包下载源失效 | 新设备无法解锁游戏 | 三级下载源回退 + 本地导入兜底 |
| 19 款游戏工作量超预期 | 周期拉长 | 严格分期，每批验收后再开下一批；难度★★以下游戏优先 |
| 孩子对某类游戏无兴趣 | 内容浪费 | M2 后先给自家孩子实测，按喜爱度调整后续批次优先级 |
| 设备碎片化（手机/平板分辨率） | 布局错乱 | 框架层统一适配规则，手机竖屏为基准，M6 集中回归测试 |

## 9. 设备与环境要求

- 开发：现有 Windows/Mac 环境 + Flutter SDK + 一台 Android 测试机
- 目标设备：家中 Android 手机（主力），竖屏 360dp 为基准；平板/桌面浏览器仅作兼容与调试场景；iOS 通过 Safari PWA 或 TestFlight 侧载体验
- 下载源：家庭 NAS 或任意静态托管（运营成本 0）

## 10. 成功标准

1. 孩子在无家长协助下，能自己打开 App、进入游戏、完成一局（3 岁段验证）。
2. 全程零广告、零误触充值、零外部跳转。
3. 护眼计时与家长门真实生效（家长自己都绕不过算术题才算合格）。
4. 两周家庭试用后，孩子有 2~3 个"最爱游戏"并主动要求玩——说明内容选对了。
