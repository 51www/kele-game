# 《童趣游戏盒》开发里程碑文档

> 版本：v1.1 ｜ 日期：2026-10-29 ｜ 技术栈：Flutter + Flame｜参考：儿童小游戏APP计划书.md、UI 设计规范.md
> 本文档将计划书 §6 的里程碑拆分为**功能模块级**可执行任务。
> **硬约束（v1.1 新增）：每个里程碑“完成/新增的游戏个数”不得超过 2 款。** 因此原计划书 M5（6 款）、M6（7 款）的大批量里程碑已拆细为 9 个每批 2 款的内容里程碑（M4~M12）；M1 框架阶段以「翻牌记忆」1 款内置游戏作为全链路验证，计入 19 款总数。
> 每阶段验收通过后再开下一批（计划书 §8 风险对策）。

---

## 0. 功能模块总览（贯穿全程的横切模块）

| 模块编号 | 模块名 | 说明 |
|---|---|---|
| M-Core | 核心框架 | 主题/路由/音频/存储、GameModule 接口、GameScaffold 外壳、统一结算 |
| M-Home | 游戏大厅 | "我的游戏"宫格 + "游戏商店"、家长中心入口 |
| M-Down | 下载管理器 | 队列/校验/解锁动画/三级源回退 |
| M-Parent | 家长中心 & 儿童保护 | 家长门、护眼计时、每日时长、游戏隐藏/删除 |
| M-Store | 进度存储 | SharedPreferences + 每游戏 json、备份导出 |
| M-Asset | 素材与主题 | 统一萌系素材库、配色对齐 UI 规范 |
| M-Adapt | 多分辨率适配 | 手机竖横为主、平板兼容，UI 与游戏画布分层 |

## 1. M0 环境验证（0.5 周）

**功能范围**：搭建 Flutter + Flame 工程，跑通一个 60fps 的 Flame demo。
**本里程碑完成游戏数：0**

### 实现步骤
1. 初始化 Flutter 工程（命名 `tongqu_gamebox`，结构对齐计划书 §4.2）。
2. 引入 Flame 依赖，建立 `core/`、`features/`、`game_engine/`、`games/` 目录骨架。
3. 编写最小 Flame demo（一个受控方块 + 60fps 帧率显示）。
4. 配置 Android 真机调试（手机优先）。

### 关键依赖
- Flutter SDK、一台 Android 测试手机（竖屏 360dp 基准）。
- 确认 `GameModule` 抽象接口与 B-1 素材包解锁方案（计划书 §4.1）。

### 验收标准
- [ ] 手机真机运行 Flame demo，稳定 60fps。
- [ ] 工程目录结构符合计划书 §4.2。
- [ ] 可重复 build/install 到测试机。

## 2. M1 框架搭建（1 周）

**功能范围**：M-Core + M-Home（空壳）+ M-Store（基础）打通全链路。以「翻牌记忆」1 款内置游戏验证框架。
**本里程碑完成游戏数：1（翻牌记忆——同时作为框架验证，计入 19 款总数）**

### 实现步骤
1. 定义 `GameModule` 抽象接口（`id/name/minAge/packSize/init/buildGamePage/pause/resume/dispose/resultStream`，对齐计划书 §4.3）。
2. 实现 `GameScaffold`：统一外壳，注入暂停/计时/返回二次确认/结算触发。
3. 实现统一结算弹窗（星星 + 分数 + "再玩一次/回大厅"两个大主按钮，源自 UI 规范 §6.3）。
4. 实现 `score_system`：星星/分数/用时 → 经 `resultStream` 上报。
5. 实现 `M-Home` 大厅骨架：九宫格卡 + 商店占位 + 家长中心入口（带 🔒）。
6. 接入 `M-Store`：SharedPreferences 落地解锁状态/分数/星级。
7. 内置「翻牌记忆」实现 `GameModule`，跑通 大厅→进入→结算→回大厅。

### 关键依赖
- UI 设计规范 §6 按钮/弹窗/卡片组件已就绪（可先用最小样式）。
- `GameModule` 接口是后续所有游戏接入的契约，必须先稳定。

### 验收标准
- [ ] 翻牌记忆经大厅全链路可玩（进入→结算→回大厅）。
- [ ] 统一结算弹窗被该游戏复用，无自造结算页。
- [ ] 分数/星级写入并回显于大厅卡片。
- [ ] 游戏内返回二次确认弹窗生效。

## 3. M2 下载系统（1 周）

**功能范围**：M-Down 完整落地，实现 B-1 素材包解锁（计划书 §4.1）。将 M1 的「翻牌记忆」改造为"首次需下载解锁"。
**本里程碑完成游戏数：0（改造既有 1 款为素材包模型，不新增游戏）**

### 实现步骤
1. 编写 `tool/` 打包脚本：zip 素材 + 生成 MD5 + `manifest.json`（`assets/packs/`）。
2. 实现下载管理器：单队列（同时仅 1 个）、Wi-Fi 才允许、MD5 校验、失败三次转"本地导入"引导。
3. 实现解锁流程：下载确认（大小/适龄奶油卡）→ 进度条 → 星星解锁动画（`motion.celebrate`）。
4. 三级下载源回退：家庭局域网 HTTP → 静态托管直链 → 设备目录本地导入。
5. 将「翻牌记忆」改造为"内置逻辑 + 素材包"，商店展示大小/适龄，未下载显示下载入口。

### 关键依赖
- M1 的 `GameModule.packSize` 与大厅商店卡样式。
- 家长端环境：家庭 NAS / 静态托管可用。

### 验收标准
- [ ] 断网后已下载游戏可玩，未下载游戏不可进（除非本地导入）。
- [ ] 下载进度条 + 解锁动画完整，体验接近"真下载"。
- [ ] 三级源回退可用；MD5 校验失败能提示并引导本地导入。
- [ ] 单队列策略生效，不出现并发下载。

## 4. M3 家长中心（0.5 周）

**功能范围**：M-Parent 全部儿童保护规则生效。
**本里程碑完成游戏数：0**

### 实现步骤
1. 家长门：算术题（两位数）+ 长按 3 秒随机轮换（计划书 §4.4），进入家长中心与删除/隐藏游戏时触发。
2. 护眼计时：连续 20 分钟强制休息动画（眼保健操 30s，不可跳过）；每日总时长可设（默认 40min，范围 20~120），到点显示"明天见"页。
3. 游戏隐藏：家长可隐藏某游戏，大厅不再展示。
4. 删除游戏：触发家长门 + 危险按钮 + 二次确认。
5. 家长中心切换为降饱和奶油底（UI 规范 §7 分区策略），与儿童区视觉隔离。

### 关键依赖
- 全局音量开关、护眼暂停由 `GameScaffold` 在游戏层统一拦截（计划书 §4.3 规则 3）。
- `M-Store` 持久化家长设置（时长、隐藏列表）。

### 验收标准
- [ ] 算术题随机轮换，家长本人也需计算才能进入（绕不过）。
- [ ] 连续 20 分钟弹休息动画且不可跳过；每日到点锁屏至次日。
- [ ] 隐藏/删除游戏均触发家长门 + 二次确认。
- [ ] 儿童区与家长中心视觉分区正确。

## 16. 跨里程碑关键依赖与风险（对齐计划书 §8）

| 依赖/风险 | 影响 | 应对 |
|---|---|---|
| `GameModule` 契约不稳定 | 后续所有游戏返工 | M1 先锁死接口，再批量接入 |
| B-1 素材包下载源失效 | 新设备无法解锁 | 三级源回退 + 本地导入兜底（M2 必做） |
| 19 款工作量超预期 | 周期拉长 | 严格分期每批 ≤2 款、验收后再开下一批；★★以下优先 |
